# 记忆系统规则

大白话:记忆就是 char "记得什么"。记错人、记串角色,就会出戏。所以这里规则最严。

## 一、两种记忆(user 可选其一或同时开)

| 种类 | 做法 | 说明 |
|---|---|---|
| 传统总结记忆 | 聊够 N 条就让模型写一段总结存起来 | N 由 user 设置;总结用「记忆总结」API |
| 纯向量记忆(重点) | 把聊天片段变成一串数字存库,聊天时按"意思接近"找回相关片段 | 用「向量记忆」API;可选「重排」API 让结果更准 |

两种都必须:能开、能关、能查看、能编辑、能删除每一条。

## 二、角色隔离(铁律)

- 每条记忆都带 `charId`(属于哪个角色)和 `userPersonaId`(对应你的哪个人设)。
- 读取时必须先按 `charId` 过滤,再做任何查找。禁止跨角色读取。
- 群聊:记忆属于"群"和"参与的每个角色各自视角"两层,角色只能读自己视角 + 群公共部分。
- 唯一例外:「打通关系表」里明确写了且 user 开了开关的互通。

## 三、向量记忆怎么做

1. **切片**:按一轮对话或一个事件切,不按字数硬切。
2. **入库**:存原文、摘要、向量、时间、重要程度、来源 App、`charId`。
3. **查找**:先过滤角色,再按意思相近度取前 K 条,可选重排。
4. **加权**:时间越近、越重要、被提到越多的越容易被找到。
5. **去重与合并**:意思几乎一样的记忆合并,避免重复占位。
6. 向量存数据库,搜索分批进行,不能一次把全部读进内存。

## 四、上下文读取深度

- user 可自定义:最近聊天读几条、读几条记忆、读多少字。
- 读取顺序和预算由「共用读取流程」统一管(见 `预设与提示词.md`),各 App 不得自己随便读聊天库。

## 五、来源与写入

每条记忆标注来源:`chat` / `meet` / `dream` / `couple` / `forum` 等。

| 来源 | 是否进记忆 |
|---|---|
| chat 聊天 | 按用户设置 |
| 相遇 | 可选(开关) |
| 栖迟 梦境 | 可选(开关);if 线番外**不进** |
| 情侣空间 | 重要事件可选 |
| 其他 App | 默认不进,打通时单独说明 |

## 六、必须有的操作

- 查看记忆列表(按角色、按来源、按时间)
- 编辑单条、删除单条、清空某角色记忆
- 导出/导入(跟随总备份)
- 记忆总结和向量化失败时:重试,且不丢原始聊天

## 七、反面清单

- 禁止把 A 角色的记忆喂给 B 角色。
- 禁止在界面线程里做向量计算。
- 禁止未经开关就把相遇/梦境内容写进记忆。
