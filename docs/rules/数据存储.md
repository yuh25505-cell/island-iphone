# 数据存储

目标：像微信/QQ 一样的成熟存储——长期保存、不卡、尽量不丢数据。

## 规则

1. 数据库用 Room（SQLite），开启 WAL，写入走后台线程，界面线程不碰数据库
2. 聊天数据分页读取（每次一屏左右，向上滚动再加载），建索引：角色+时间、会话+时间
3. 大内容（图片、语音、字体、音乐）存文件，数据库只存路径
4. 定期自动备份到本地；每次大版本升级前先备份
5. 导出/导入备份：一个压缩包，含数据库、文件、设置；导入前校验、可选「合并」或「覆盖」
6. 写入使用事务，意外退出不丢已确认的数据
7. 数据库升级必须写迁移，不允许清库
8. 清空数据必须二次确认（专属弹窗），清空前提示先备份
9. 每个 char 的数据按 char_id 分开
10. 预留 GitHub 云备份接口
11. 「数据与存储」页显示各类数据占用，可单独清理缓存
