# 数据存储规则

大白话:数据存得稳、不丢、不卡,和微信、QQ 同一种思路。

## 一、基本做法

- 用系统数据库(Room,底层是 SQLite),开写前日志模式,崩溃时更不容易丢数据。
- 大文件(图片、音频、字体)存文件,数据库只存路径。
- 所有存取只通过 `data/` 里的存取层,界面不直接碰数据库。

## 二、升级不丢数据(最重要)

- 数据库每次改结构,必须写**迁移**,把旧数据带到新结构。
- **禁止**"失败就清库重建"这种自动删除设置。
- 迁移要在旧版本数据上实测过才算完成。

## 三、覆盖安装

要让新包直接盖住旧包,同时满足三件事:
1. 包名不变:`com.island.phone`。
2. 签名不变:一直用同一把密钥(GitHub 里那 4 个密钥)。
3. 版本号(versionCode)比旧包大:每次更新必须升 `version.properties`。

缺一不可。密钥丢了就永远无法覆盖安装,务必让 user 自己备份好密钥文件。

## 四、性能

- 聊天记录分页读取,滚动时按需加载。
- 常查的字段建索引(`charId`、时间、会话 ID)。
- 写入放在后台线程,批量写入用事务。
- 向量搜索分批,不一次全读。
- 精细缓存:最近会话、头像、角色资料放内存缓存,有大小上限。

## 五、备份与清理

- **导出/导入备份**:一键打包全部数据(聊天、记忆、设定、设置)。
- **API 导出/导入**:单独备份 API 设置,导出文件里的密钥要提醒 user 妥善保管。
- **清空数据**:二次确认,清空前建议先备份。
- **数据与储存**页:显示各类数据占用,可单独清理缓存。
- 预留云端备份接口(后续接 Cloudflare)。

## 六、离线

- 除 AI 调用、登录、网易云、美团定位、更新检查外,所有功能离线可用。
- 网络失败时保留已输入内容,提示可重试,不吞用户输入。

## 七、保活相关数据

- AI 回复进行中,已收到的内容边收边存,切后台或被杀进程后回来能接上或至少保留已收部分。
- 未完成的请求有状态记录:进行中 / 完成 / 失败。
