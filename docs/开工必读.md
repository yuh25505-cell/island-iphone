# 开工必读(总入口)

这份只做一件事:告诉我每次开工该去读哪几份。具体规则都在各主题文档里,这里不重复。

---

## 一、每次开工的固定步骤

1. 读完这份文档。
2. 打开 `docs/开发计划.md`,找到**当前要做的那一个任务**。一次只做一个。
3. 看任务里写的"读什么",按下面第二节的表,把对应文档读完。
4. 如果是新 App 或新功能,先按第三节写清"读取什么、保存什么",再动手。
5. 动手前确认:没涉及的代码不动。
6. 做完按第五节的格式交代。

## 二、什么任务读什么

| 任务类型 | 必读 |
|---|---|
| 任何涉及界面、页面、弹窗 | `docs/rules/界面与主题.md`、`docs/rules/用户空间.md` |
| 任何涉及存数据、读数据、备份 | `docs/rules/数据存储.md` |
| 任何涉及记忆、聊天上下文 | `docs/rules/记忆系统.md` |
| 任何涉及世界书或让 AI 生成内容 | `docs/rules/世界书管线.md`、`docs/rules/预设与提示词.md` |
| 新增 App 或新增文件 | `docs/rules/代码结构.md` |
| 做 App 之间互通 | `docs/打通关系表.md` |
| 做预设、提示词、驱动系统 | `docs/rules/预设与提示词.md` |
| 做登录、邀请码、用户创建内容 | `docs/rules/用户空间.md` |
| 打包、签名、升级安装 | `docs/rules/数据存储.md`、`.github/workflows/build.yml` |

拿不准读哪份,就多读,不要少读。

## 三、新 App / 新功能动手前,先写清两件事

- **读取**:要读哪些信息(角色资料、用户资料、世界书、记忆、最近聊天……)。
- **保存**:结束后要保存什么、存到哪、会不会进记忆。

要改共用部分(共用读取流程、共用组件、数据库结构)时,先列出会影响到哪些已有功能,改完逐个检查。

## 四、长期规则(必须遵守)

**A. 新增内容和功能**
- 新增 user 能创建的内容,必须同时做编辑和删除。
- 新增能开启的功能,必须同时做关闭方式。

**B. 代码组织**
- 按功能和职责分文件,每个文件只管一类事。
- 文件太长或混了多个功能,要及时拆分;多个 App 共用的部分统一维护。
- 新功能沿用已有结构;整理代码后检查原有功能是否正常。
- 更新优化时,不能随意删除没涉及到的代码,涉及到的才可以改或删。

**C. 界面**
- 所有页面、弹窗、功能适配:日间、夜间、跟随系统,以及"软件关闭跟随系统时"的日间/夜间手动切换。默认跟随系统。
- 所有页面、弹窗支持原生左滑、右滑返回上一步。
- 所有弹窗使用专属弹窗样式。
- 不加小字注释和说明文字。
- 全局复刻苹果原生手机的视觉、交互、配色、动效,但不要液态玻璃效果。

**D. 交付习惯**
- 每次更新或优化默认升版本号。
- 每次回复交代:改了什么、改了哪些文件、一共改了几个文件。
- 用大白话讲,不用术语。

**E. 预设和提示词**
- 系统提示词拆成多个模块,user 可自定义排序和新增模块。
- 角色资料、用户资料、世界书、记忆的读取做成共用流程;每个 App 只补自己的玩法、场景、任务、回复格式。
- 最近聊天与记忆按需选取;角色之间的数据必须隔离。

## 五、每次做完的交代格式

```
【改了什么】用大白话讲,2~5 句
【改了哪些文件】逐个列出路径
【一共改了】N 个文件
【新版本号】vX.Y.Z(versionCode N)
【你怎么验收】点哪里、看到什么算对
```
